# おくすりレスキュー

災害で手元の薬を失った人に、別の地方に預けた本人の薬を届ける Web アプリ（デモ）。
本人の薬の7日分を自宅と別の地方の「薬バンク」で預かっておき、災害が起きたら、
道路の寸断とドローンの便の数から、間に合う人数が最大になるように届ける。

画面の人・地区・薬局・道路・数字は架空のデモデータ。薬バンクやドローン会社との協定はまだない。
`noto.js` だけは珠洲市の公開データ（孤立集落・避難所の位置）を使う。

## 動かし方

公開版（GitHub Pages）：https://vpgkotaro-jpg.github.io/okusuri-rescue/ （サーバーがないので、送る記録は端末にたまったままになる）

ソース：https://github.com/vpgkotaro-jpg/okusuri-rescue

```
OKUSURI_STAFF_KEY=一覧を見る鍵 OKUSURI_DEVICE_KEYS='{"dev-ab12":"端末の鍵"}' node server.js
# http://localhost:8080/ を開く（Node 18 以降。外部ライブラリなし）
```

係員の端末の画面「この端末の鍵」に、`OKUSURI_DEVICE_KEYS` に登録した鍵を入れると、読み取り記録をサーバーへ送れる。
`index.html` をブラウザで直接開いても動く（サーバーへの送信とオフライン動作はない）。カメラは https か localhost のときだけ使える。

| URL の末尾 | 場面 |
|---|---|
| `#lost` | 患者アプリ：家が壊れて手元の薬を失った |
| `#triage` | 係員の端末：地図・届ける順番 |
| `#cap` | ドローン1拠点1日1便のときの比べ方 |
| `#card` | 避難所カードを読み込んだあと |

## 中身

### 配送計画
一人ずつ「飛べる拠点」と「届けてよい日の区間」がある。締切は手元の日数に、薬の分類ごとの猶予（即時中断不可は0日、48〜72時間以内に確保は2日）を足した日。

- 1便1人分：締切が早い人から、空いた枠か、入っている人を別の拠点・日へ移して空く枠を探して入れる（増加路）。全探索と比べたテストは、1問1〜8人・拠点1〜3つの3,000問で人数が全部一致した。
- 同じ問題を最大流（Dinic 法。拠点・届けられる日・締切が同じ人を1つの点にまとめる）でも解いた。人数は3,000問で一致し、10万人では増加路 約0.85秒に対して Dinic 14ms だった（Apple M1・Node 24、`node bench.js`）。
- 避難所単位：1便は1つの避難所へ、最大 K 人分を運ぶ。便を避難所で分けなくてよいとした最大流を上界にして、流れを便に丸め、行き先を決めてからもう一度最大流で人を入れる。締切順の貪欲法で決めた行き先でも同じように入れ直し、多く間に合う方を採る。1問1〜8人・避難所1〜3つ・拠点1〜2つの3,000問で、全探索と全部同じだった（大きな問題で最適とは限らない）。10万人・避難所400で約0.2秒。
- 1便1人分では、増加路が「締切順で飛ばす」方法より良くなったのは拠点が横に並ぶ架空の町（1,000人で117人→100人、1万人で82人→0人）だけで、デモの町と珠洲市では同じ人数だった。1便に何人分か積む場合は、同じ便の数・同じ積み方で比べても、珠洲市（12km・1便）で「飛ばす」24人に対して21人、架空の10万人の町（1拠点1日250便）で7,237人に対して4,957人だった。架空の1万人の町では同じ148人。

### QR 読み取り
生成は Project Nayuki の実装（MIT）の移植。読み取りは規格の手順から書いた。

- 曲げた紙のために、位置合わせパターンを全部探し、隣り合う4点の区画ごとに射影変換するようにした。区画の外側の縁は2次式で外挿する。それでも読めなければ3次の多項式を当てはめる。
- 曲げた紙の合成画像240枚（デモのカード・型番14〜15、曲がり0〜86度）：改良前63枚、改良後225枚、jsQR 68枚。曲がり29〜52度では13枚→60枚（60枚中）、69〜86度では0枚→52枚。曲がりが大きい画像では1枚に0.1〜0.2秒かかる
- 曲げていない合成画像200枚：自作191枚、jsQR 101枚。ぼかしを足すと自作78枚、jsQR 85枚で、ぼかしには jsQR のほうが強い
- 実機（iPhone 14、改良前の版）：印刷したカードを20回読み17回。明るい所の正面・斜め約30度・少し暗い所の15回はすべて読め、紙を曲げた5回は2回。改良後の版の実機ではまだ測っていない

### 署名と記録
- カードの登録内容（ID・名前・薬・預け先・最後の交付・発行日・期限）に、薬バンクが ECDSA P-256 で署名する。アプリとサーバーは公開鍵だけを持つ
- 手元の日数は本人の申告。交付の記録から出した上限（交付した日数 − 交付からの日数）より多ければ上限で頭打ちにする。少なければ（失った・壊れた）そのまま順番に使い、「申告を要確認」の印をつけて係員が確かめる
- サーバーは、端末ごとの鍵で付けた HMAC が合う記録だけを受け取る。記録の ID は端末 ID で始まるものだけ受け付けるので、ほかの端末の記録は上書きできない
- 患者アプリの「手元の薬を失った」は端末にため、通信が戻ったら `POST /api/lost` へ送る。サーバーはカードの署名で確かめ、カード1枚につき1件にまとめる

## まだできていないこと

- ログインと医療情報の暗号化（カードに薬の名前が平文で載る）
- 「失った」はカードの文を持っている人なら誰でも送れる。係員が確かめるまでは申告の扱い
- 実際の道路の通行情報とのつなぎ込み（デモの地図は手で開け閉めする。珠洲市の計算は県の孤立集落の一覧を使う）
- 改良後の QR 読み取りを実機で測ること。Android での計測。実際の写真での jsQR との比較
- 避難所単位の計画は、大きな町では上界との差が残る（1万人・避難所100で、上界0人に対して148人）
- 最初に預ける7日分は、手元の残薬を宅配で預けるか、卸の在庫を引き当てて始める想定。費用を誰が持つかは決まっていない
